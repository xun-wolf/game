# 《田间风云》前期动画优化方案

> 范围：开机 → 主菜单 → 开场卷轴 → 进入第一候（含首屏手牌、立春横幅、教程卷轴）
> 引擎约束：Godot 3.5.3 / GLES2 / Windows + HTML5
> 结论类型：方向评审 + 实施任务清单（本文档不含代码改动）

---

## 一、现状审计

| 模块 | 现有实现 | 位置 | 问题 |
| :--- | :--- | :--- | :--- |
| 开场卷轴 | `AnimationPlayer` 四段文字整体淡入，点击 `seek` 到末尾 | `GameIame/Intro.gd`、`Intro.tscn` | 只有透明度变化，没有“卷轴展开/逐字书写”的叙事感；跳过是硬切 |
| 主菜单 | 静态背景 + 播放按钮 | `MainMenu.tscn`、`ui/MainMenu.gd` | 首屏完全静止，第一印象偏“工程 demo” |
| 场景转场 | `AnimationPlayer` 全屏淡出/淡入 | `SceneTransitions.gd` | 通用黑场，缺少田园/水墨主题 |
| 季节横幅 | `lerp` 透明度，3.8 秒后淡出 | `ui/SeasonBanner.gd` | 只有淡入淡出，没有展开或墨迹 |
| 四季粒子 | `CPUParticles2D`（花瓣/浮尘/落叶/雪）双层 | `seasons/SeasonFX.gd` | 切换时直接 `visible` 开关，硬切；无切换瞬间的爆发 |
| 手牌 | 每帧 `position += (target - position) * 0.15` 式插值 | `cards/HandCard.gd` | 帧率相关、无发牌入场、悬停无阴影/倾斜、无扇形弧线 |
| 体力球 | 双层贴图反向旋转 + 数值平滑 | `energy/EnergyOrb.gd` | 已可用；缺“体力不足”的反馈动画 |
| 镜头 | 跟随 + 震屏 | `Camera.gd` | 已可用；震屏缺乏分级 |
| 作物抖动 | 随机位移 | `plants/JitterFX.gd` | 随机跳变，缺少正弦呼吸感 |

**核心判断**：动画能力不是“没有”，而是**缺少叙事层与节奏层**。现有实现以“能过渡”为目标，首屏缺少“开场演出”，交互反馈缺少“打击感”，且手牌动画存在帧率依赖的工程隐患。

## 二、外部案例（9 个）

评分口径：适配性 / 成本（5 = 最省）/ 预期效果，满分 5 分。

### 案例 1｜Godot Card Game Framework（db0）

- 来源：<https://github.com/db0/godot-card-game-framework>（Asset Library 标注 Godot 3.4）
- 技术栈：Godot 3.x + GDScript + `Tween`
- 实现方式：手牌椭圆/直线两种布局；增删卡自动重排；悬停自动聚焦并抬升；拖拽落桌、牌堆、目标箭头，全部用 Tween 串接
- 视觉特点：卡牌移动有缓入缓出、悬停卡放大上浮、牌堆用厚度表达数量
- 可复用价值：**手牌重排与悬停聚焦的时序设计**，与当前 `HandCard.gd` 的状态机（IN_HAND/HOVER/PICKUP/DISCARD）几乎一一对应，可原地替换插值实现
- 评分：适配 5 / 成本 3 / 效果 5

### 案例 2｜gcard_layout（cyanglaz）

- 来源：<https://github.com/cyanglaz/gcard_layout>（Asset Library 2971）
- 技术栈：Godot 4 + GDScript（Control 节点）
- 实现方式：与节点解耦的“布局数据”方案，按索引计算弧线角度、X 偏移与 Y 抬升；悬停参数可配置，编辑器内实时预览
- 视觉特点：TCG 扇形手牌，牌面沿弧线旋转，悬停时旋转归零并上浮
- 可复用价值：**弧线布局数学**（角度步进、`cos` 抬升、pivot 约定）可直接移植到 3.5；编辑器预览思路可用于调参
- 评分：适配 4 / 成本 5 / 效果 4

### 案例 3｜TCG-Hand-Layout（Jaete，.NET 版）

- 来源：<https://github.com/Jaete/TCG-Hand-Layout>
- 技术栈：Godot .NET / C#
- 实现方式：gcard_layout 的 C# 重写，新增“悬停时是否置顶”的 z-index 选项、拖拽（Beta）、编辑器实时预览
- 视觉特点：与案例 2 一致，额外解决了“悬停卡被相邻卡遮挡”的层级问题
- 可复用价值：**z-index 规则与 pivot 约定**；代码本身不适合混入 GDScript 工程
- 评分：适配 2 / 成本 5 / 效果 3

### 案例 4｜Godot 简单溶解 Shader

- 来源：<https://godotengine.org/qa/27416/how-to-create-a-simple-dissolve-shader>
- 技术栈：Godot 3.x `canvas_item` Shader + 噪声贴图
- 实现方式：采样噪声灰度与 `progress` 比较，用 `smoothstep` 控制透明度；由 `Tween` 或 `AnimationPlayer` 驱动 uniform
- 视觉特点：纸张/墨迹被“擦除”或“显影”，可做边缘加深的烧蚀感
- 可复用价值：**开场卷轴显影、菜单→游戏转场、卡牌弃置消散**三处共用一套 Shader
- 评分：适配 5 / 成本 4 / 效果 5

### 案例 5｜Universal Transition Shader

- 来源：<https://godotengine.org/asset-library/asset/4148>
- 技术栈：Godot 4.4 Shader 集合
- 实现方式：方向擦除、径向时钟、Iris/多边形揭示、溶解、滑动等参数化转场
- 视觉特点：同一套接口切换多种转场风格
- 可复用价值：**转场类型学参考**；3.5/GLES2 只需移植“墨迹溶解 + 卷轴展开”两种，不必引入整套
- 评分：适配 3 / 成本 3 / 效果 4

### 案例 6｜打字机文字（Godot 3.5）

- 来源：<https://godotengine.org/qa/19083/animating-typewriter-text>、<https://drentsoftgames.com/godot-quick-tip-typing-text-effect/>
- 技术栈：Godot 3.5 `Label.visible_characters` / `RichTextLabel`
- 实现方式：按时间累加可见字符数；标点处短暂停顿；点击一次补全当前段
- 视觉特点：逐字书写，配合纸张底可形成“落笔”感
- 可复用价值：**开场卷轴与教程文本**；实现成本极低，且天然支持“跳过”
- 评分：适配 5 / 成本 5 / 效果 4

### 案例 7｜Godot 2D 粒子系统（官方文档）

- 来源：<https://docs.godotengine.org/zh-cn/3.x/tutorials/2d/particle_systems_2d.html>
- 技术栈：`CPUParticles2D`（GLES2 推荐）
- 实现方式：发射矩形/点、`preprocess` 预热、颜色与缩放随机、双层远近景
- 视觉特点：春夏秋冬的环境氛围；当前工程已用该方案
- 可复用价值：**切换季节时的交叉淡入 + 单次爆发**；不改技术栈，只补时序
- 评分：适配 5 / 成本 4 / 效果 4

### 案例 8｜Balatro 的 Game Feel 拆解

- 来源：<https://teemo.dev/game-design/balatro/systems/game-feel-and-juice/>、<https://blakecrosley.com/guides/design/balatro>
- 技术栈：商业引擎（Unity），但方法论与引擎无关
- 实现方式：同一时刻只让一个元素大幅运动；卡牌“挤出→回弹”的 squash & stretch；数字按颜色弹出；震屏强度随数值分级；手牌持续微动
- 视觉特点：廉价贴图也能产生“厚重手感”
- 可复用价值：**出牌/收获反馈的分层与时序规范**（先卡牌、再数字、再震屏、最后音效）
- 评分：适配 5 / 成本 5 / 效果 5

### 案例 9｜“Juice it or lose it”（2012 演讲）

- 来源：<https://media.gdcvault.com/gdc2016/Presentations/Eiserloh_Squirrel_JuicingYourCameras.pdf>（引用该演讲）
- 技术栈：方法论
- 实现方式：在不改玩法逻辑的前提下叠加补间、粒子、震屏、音高变化、挤压拉伸
- 视觉特点：从“表格”变成“游戏”
- 可复用价值：**评审清单**：每个交互至少回答“位移/缩放/粒子/音效/颜色”五项中用了哪几项
- 评分：适配 5 / 成本 5 / 效果 4

## 三、团队评审

参与角色：主美、客户端程序、技术美术（TA）、玩法策划、制作人/QA。
评审规则：每项按“适配性（能否在 3.5/GLES2 落地）、成本、预期效果、风险”讨论，冲突时以“不干扰读牌”为最高优先级。

### 会议纪要（摘要）

**主美**：
> 开场不能做成通用弹跳。我们要的是“旧卷轴被展开、墨迹慢慢显出来”，所以打字机 + 墨迹溶解是主线；菜单标题可以做轻微呼吸和纸纹视差，但不要漂浮乱晃。

**客户端程序**：
> 手牌现在用固定系数插值，帧率一掉手感就变，这是必须先修的。方案 1 的时序 + 方案 2 的弧线数学够用，不需要引入第三方插件；全部用 3.5 的 `Tween` 和 `AnimationPlayer` 实现。转场的屏幕纹理在 GLES2 有限制，必须保留黑场 fallback。

**技术美术**：
> 溶解 Shader 一套就够：开场做“显影”，转场做“擦除”，弃牌做“消散”，只换参数和噪声图。粒子不用换方案，补交叉淡入和切换爆发即可。不要上全屏后处理，HTML5 会掉帧。

**玩法策划**：
> 局内动画必须短：悬停 ≤0.18 秒、出牌 ≤0.25 秒、收获反馈 ≤0.6 秒，且同一时刻只有一个视觉焦点。开场可以慢，但必须一键跳过；教程文字要能点击补全。

**制作人/QA**：
> 分三批做：P0 只碰首屏与手牌，保证可回退；P1 补局内反馈；P2 再考虑转场库和减弱动效开关。每批都要过 `_devtest/autotest.tscn` 截图和 HTML5 导出验证。

### 评审结论

| 方案 | 采纳程度 | 说明 |
| :--- | :--- | :--- |
| 案例 1 手牌时序 | 采纳（P0） | 替换现有帧率相关插值 |
| 案例 2 弧线数学 | 采纳（P0） | 只移植计算，不引入插件 |
| 案例 3 .NET 实现 | 不采纳代码 | 只借鉴 z-index 与 pivot 规则 |
| 案例 4 溶解 Shader | 采纳（P0） | 一套 Shader 三处复用 |
| 案例 5 转场库 | 部分采纳（P1） | 只做墨迹/卷轴两种 |
| 案例 6 打字机 | 采纳（P0） | 开场与教程共用组件 |
| 案例 7 粒子 | 采纳（P1） | 补交叉淡入与爆发 |
| 案例 8/9 方法论 | 采纳（规范） | 写入验收清单 |

## 四、优化方向与实施任务

### 4.1 三条原则

1. **叙事优先**：首屏允许慢，但每一段都必须可跳过；局内动画必须为读牌让路。
2. **一次一个焦点**：同一时刻只允许一个元素做大幅度运动（Balatro 原则）。
3. **先修隐患再叠加**：手牌的帧率相关插值必须先改成 `Tween`/`delta` 驱动，再加新效果。

### 4.2 P0：首屏三件套 + 手牌基础

#### T1 开场四幕卷轴分镜（已实现）

> 已被 [开场动画重构方案.md](开场动画重构方案.md) 取代：移除飘雪，改为「农书墨痕 → 灯下成牌」。

- 文件：`GameIame/Intro.tscn`、`Intro.gd`，共用 `GameIame/shaders/ink_wipe.shader`
- 叙事：荒芜 → 石下卷轴 → 四季成牌 → 接牌入田；四句短字幕，不再使用整段旁白
- 画面：用现有 `decor`（树/石/草丛）、`tutorial/scroll.svg`、四张卡面与 `title_cn.png` 分层合成；`Stage` 节点做推近与位移，雪花/灰尘由 `CPUParticles2D` 生成
- 交互：点击/空格推进一幕，长按 0.6 秒或 ESC 跳过；`user://intro_seen.json` 记录已看，回访极简版由主菜单开关「回访时播放极简开场」控制（默认关闭，即每次播放完整版）
- 收尾：`SceneTransitions.change_scene_to(GS.Game)`，沿用墨迹转场，教程流程不变
- 验收：四幕自动/点击推进、跳过、结束跳转与已看标记均通过用例（详见第六节）

#### T2 主菜单入场

- 文件：`MainMenu.tscn`、`ui/MainMenu.gd`（只加动画，不改按钮逻辑）
- 做法：标题用 `AnimationPlayer` 做 0.8 秒缩放+透明度；背景两层做缓慢反向位移（±8px、周期 12 秒）；按钮 hover 用 `Tween` 做 0.95→1.05→1 的挤压
- 技术选择：定值动画用 `AnimationPlayer`（官方推荐用于已知终值的淡入淡出），动态反馈用 `Tween`

#### T3 墨迹转场（保留 fallback）

- 文件：`SceneTransitions.tscn`、`SceneTransitions.gd`，新增 `shaders/ink_transition.shader`
- 做法：全屏 `ColorRect` + 噪声溶解，`progress` 0→1；完成后 `change_scene_to`，再 1→0 揭开；GLES2 屏幕纹理不可用时自动退回现有 `FadeOutIn`
- 验收：转场总时长 0.6~0.8 秒，期间输入锁定，结束后恢复

#### T4 手牌：扇形布局 + 悬停 + 发牌入场

- 文件：`cards/HandCard.gd`、`cards/CardManager.gd`
- 做法：
  1. 用弧线公式计算每张牌的目标位置/角度（移植案例 2）
  2. 用 `Tween` 替换 `position += (target - position) * 0.15`，消除帧率依赖
  3. 悬停：`scale 1.0→1.22`、`y -36px`、旋转归零、`z_index 100`、阴影加深
  4. 发牌：按索引 `0.04s` 递增延迟，从牌堆位置飞入
- 代码示意：

```gdscript
const MAX_ANGLE := 0.45   # 约 26 度
const ARC_LIFT := 26.0

func fan_transform(i: int, total: int) -> Dictionary:
	var t := 0.0
	if total > 1:
		t = float(i) / float(total - 1) * 2.0 - 1.0
	return {
		"position": Vector2(t * 380.0, ARC_LIFT * (1.0 - cos(t * MAX_ANGLE))),
		"rotation": t * MAX_ANGLE
	}

func tween_to(pos: Vector2, rot: float, sc: float, duration := 0.18):
	$Tween.stop_all()
	$Tween.interpolate_property(self, "position", position, pos, duration,
		Tween.TRANS_CUBIC, Tween.EASE_OUT)
	$Tween.interpolate_property(self, "rotation", rotation, rot, duration,
		Tween.TRANS_CUBIC, Tween.EASE_OUT)
	$Tween.interpolate_property(self, "scale", scale, Vector2(sc, sc), duration,
		Tween.TRANS_BACK, Tween.EASE_OUT)
	$Tween.start()
```

#### T5 首屏横幅与教程卷轴入场

- 文件：`ui/SeasonBanner.gd`、`tutorial/Tutorial.tscn`
- 做法：横幅由“中间向两侧展开”（`rect_scale.x 0.86→1`）+ 墨迹淡入；教程卷轴从上方 20px 滑入；两者都可点击立即收起

### 4.3 P1：局内反馈与季节氛围

#### T6 季节粒子交叉淡入

- 文件：`seasons/SeasonFX.gd`
- 做法：切换时旧发射器 0.4 秒淡出后再隐藏（用 `Tween` 改 `modulate` 或 `amount`），新发射器同时淡入；切换瞬间触发一次 0.5 秒的 `one_shot` 爆发（花瓣/落叶/雪）
- 注意：当前 `visible=false` 会冻结粒子，必须同步清空旧粒子

#### T7 收获/出牌反馈分层

- 文件：`cards/HandCard.gd`、`ui/NewCardSelection.gd`、`GoldLabel.gd`
- 顺序：卡牌挤压 1.0→0.92→1.04→1.0（0.18 秒）→ 金币数字弹出（`scale 0.6→1.15→1` + 上浮 24px + 淡出）→ 轻震屏 0.08 秒 → 音效
- 规范：同一时刻只触发一条链路；数字弹出不超过 0.6 秒

#### T8 牌堆数量可视化

- 文件：`cards/CardManager.gd`
- 做法：抽/弃牌堆用 2~3 张错位叠放表达厚度，数量变化时补间偏移；仅视觉，不影响逻辑

### 4.4 P2：扩展与可选

- 转场库扩展（卷轴横向展开、墨迹从四角聚合）
- 卡牌弃置溶解（复用 T1 Shader）
- “减弱动效”开关：停用粒子、缩短/关闭位移，保留淡入淡出
- 暂停菜单、商店的入场动画统一到同一套缓动曲线

### 4.5 统一规范

| 场景 | 时长 | 缓动 | 备注 |
| :--- | :--- | :--- | :--- |
| 悬停/抬起 | 0.15~0.18s | Cubic Out | 不打断读牌 |
| 出牌/收割 | 0.18~0.25s | Back Out（轻微） | 只允许一张牌动 |
| 数字弹出 | 0.45~0.6s | Cubic Out | 与音效同步 |
| 转场 | 0.6~0.8s | Sine InOut | 输入锁定 |
| 开场逐字 | 24~30 字/秒 | 线性 | 标点停 0.08s |
| 季节切换 | 0.4s 淡入 + 0.5s 爆发 | Sine | 旧粒子先清空 |

## 五、验收与测试

1. **功能**：开场任意时刻点击可补全并翻页；“减弱动效”开启后不出现大幅位移。
2. **性能**：1080×800 / GLES2 下平均 ≥55 FPS；HTML5 导出无 Shader 编译错误。
3. **回归**：`_devtest/autotest.tscn` 增加 4 个截图点（启动、菜单、开场第二段、首候手牌），全部 `err=0`。
4. **手感**：手牌悬停/出牌在 30 FPS 与 144 FPS 下手感一致（验证已去除帧率依赖）。
5. **可读性**：局内任意动画不得遮挡手牌文字超过 0.3 秒。

| 风险 | 影响 | 对策 |
| :--- | :--- | :--- |
| GLES2 屏幕纹理限制导致转场 Shader 失败 | 黑屏/花屏 | 保留 `FadeOutIn` fallback，按 `OS.get_current_video_driver()` 或首帧测试自动降级 |
| 3.5 `Tween` API 与 4.x 教程不一致 | 代码不可用 | 统一用 `interpolate_property` + `TRANS_*`/`EASE_*`，禁止照搬 4.x `create_tween()` |
| 手牌动画与拖拽状态冲突 | 卡牌卡住 | 保留现有状态机，Tween 只改表现层，不改状态 |
| 粒子/Shader 在 HTML5 掉帧 | 首屏卡顿 | 粒子数量不增，转场用贴图位移替代全屏采样作为兜底 |
| 动画过多干扰读牌 | 体验下降 | 执行“一次一个焦点”与时长上限，评审清单逐条过 |
