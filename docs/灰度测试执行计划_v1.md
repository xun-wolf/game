### 1.1 实验组 / 对照组

| 组 | 数值 | 用途 |

| 对照（旧） | 体力道具 10；一品修渠 8；固定虫王 9 血 | 只在 P1 内部做少量对照 |

### 1.2 指标定义（全部来自 `run_stats.jsonl`）

| 指标 | 计算方式 |
|---|---|
| 完税率 | `passed == true` 或 `golden_rice == true` 的局数 / 该档总局数 |
| 平均剩余金币 | 仅统计 `end == "tax"` 且 `passed == true` 的局：`gold - tax` 的均值 |
| 首件体力购买率 | `purchases.Shop1 >= 1` 的局数 / 总局数 |
| 两件以上购买率 | `purchases.Shop1 + purchases.Shop2 >= 2` 的局数 / 总局数 |
| 固定虫王 TTK | `king_alive_turns / king_kills`（仅统计 `king_kills > 0` 的局） |
| 金稻达成率 | `golden_rice == true` 的局数 / 总局数 |
| 收获结构 | 各档 `harvests` 均值、`gold_choices / (gold_choices + card_choices)` |

> 统计文件位置（Windows）：`%APPDATA%\Godot\app_userdata\田间风云\run_stats.jsonl`
> 每局结束时自动追加一行；测试开始前必须先备份并清空，避免混入开发期数据。

## 三、P1 内部测试（2 天）

### 3.1 人员与样本

| 角色 | 人数 | 任务 |
|---|---|---|
| 测试 A（老手） | 1 | 三品、一品各 3 局（新数值） |
| 测试 B（新手） | 1 | 九品、七品各 3 局（新数值） |
| 测试 C（数值） | 1 | 五品 3 局（新数值）+ 三品/一品各 2 局对照（旧数值） |

- 合计：新数值 15 局，旧数值 4 局；每天约 10 局。
- 机器与构建：同一台 Windows 机器、同一份导出版本（`5.3.3` 引擎、相同分辨率）。

### 3.2 每日执行清单

1. 备份并清空 `run_stats.jsonl`，记录清空时间。
2. 启动游戏 → 主菜单勾选（或关闭）“平衡 v1 测试” → 选择指定品级 → 完整打完一局（含结算/胜利）。
3. 记录：开局时间、是否遇到虫王、体感备注（一句话即可）。
4. 每局结束后不关闭游戏，直接开下一局。
5. 当日结束导出日志：
   ```powershell
   Copy-Item "$env:APPDATA\Godot\app_userdata\田间风云\run_stats.jsonl" "D:\aigame\_shots\gray_p1_$(Get-Date -Format yyyyMMdd).jsonl"
   ```
6. 用第四节脚本汇总，填入日报模板。

### 3.3 P1 出口条件

- 无脚本错误、结算正常（`golden_rice` 与 `tax` 两种结局都能写入）。
- 九品完税率 ≥80%，一品完税率 ≥40%（允许小样本波动，但低于下限需先查原因）。
- 虫王 TTK 落在 2–3 候。
- 满足 → 进入 P2；不满足 → 先按第五节“参数回退表”调一档，再重跑 P1。

## 四、数据汇总脚本（一次性，不入库）

```python
import json, os, statistics, collections

PATH = os.path.expandvars(r"%APPDATA%\Godot\app_userdata\田间风云\run_stats.jsonl")

def load():
    rows = []
    with open(PATH, encoding="utf-8") as f:
        for line in f:
            line = line.strip()
            if line:
                rows.append(json.loads(line))
    return rows

rows = load()
by_tier = collections.defaultdict(list)
for r in rows:
    by_tier[r["tier"]].append(r)

for tier, rs in sorted(by_tier.items()):
    n = len(rs)
    wins = sum(1 for r in rs if r["passed"] or r["golden_rice"])
    taxed = [r for r in rs if r["end"] == "tax" and r["passed"]]
    leftover = statistics.mean([r["gold"] - r["tax"] for r in taxed]) if taxed else 0
    first_orb = sum(1 for r in rs if r["purchases"].get("Shop1", 0) >= 1) / n
    two_orb = sum(1 for r in rs if r["purchases"].get("Shop1", 0) + r["purchases"].get("Shop2", 0) >= 2) / n
    kills = sum(r["king_kills"] for r in rs)
    ttk = sum(r["king_alive_turns"] for r in rs) / kills if kills else 0
    rice = sum(1 for r in rs if r["golden_rice"]) / n
    print(f"tier={tier} n={n} win={wins/n:.0%} leftover={leftover:.1f} "
          f"first_orb={first_orb:.0%} two_orb={two_orb:.0%} king_ttk={ttk:.1f} rice={rice:.0%}")
```

判定区间（来自平衡方案 §6.1）：

| 指标 | 区间 |
|---|---|
| 完税率 | 九品 80–90%、七品 70–80%、五品 60–70%、三品 50–60%、一品 40–55% |
| 平均剩余金币 | 0–8 |
| 首件体力购买率 | 60–75% |
| 两件以上购买率 | 15–35% |
| 固定虫王 TTK | 2–3 候 |
| 金稻达成率 | 九品 25–35%、一品 5–10% |

## 十、风险与规避

| 风险 | 规避 |
|---|---|
| 日志混入开发/自动测试数据 | 分发前清空 `run_stats.jsonl`；测试者机器不跑 autotest |
| 样本小导致误判 | 每档 ≥30 局；P1 只作方向判断，不据此大改 |
| 测试者不按品级玩 | 分配表写清品级，日志中的 `tier` 字段可校验 |
| 导出模板缺失 | 导出前在编辑器确认 Windows 模板已安装；失败则改用编辑器导出 |
| 局中切换开关造成混淆 | 开关只对新开一局生效，并在说明中注明 |
| 只看数字忽略体感 | 每局必须写一句体感，尤其是“修渠是否打断节奏”“虫王是否有压迫感” |
