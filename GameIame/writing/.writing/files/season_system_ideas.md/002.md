# 四季系统设计想法记录

## 背景

目标是在现有地图上实现"同一张地图、四个季节"，并让季节随游戏轮次自动切换。

春季沿用项目原始素材；夏、秋、冬三套素材已基于原图生成，保持像素轮廓与明暗结构，只调整配色和季节细节。本文记录已经确认的事实、设计想法、待定问题和实现思路，作为后续讨论与开发的共同依据。

### 各季视觉方向

- 春：原始亮黄绿色，作为基准
- 夏：植被转为深绿色。树冠主色由约 `RGB 95,203,57` 压到约 `RGB 42,159,60`；草地绿色均值由 `84,189,53` 降到 `38,135,38`；泥土同步压暗，花朵保持鲜艳作为点缀
- 秋：草地转为枯黄/土黄，落叶树按区域混合金、橙、枫红；松树保持常绿；地表散布落叶斑点
- 冬：地面覆雪，树冠顶部积雪，枝叶去饱和为霜蓝灰；花、石头、树桩带雪；农田呈雪下垄沟

### 作物与轮次

游戏当前没有全局轮次计数器。每个"结束回合"走一遍 `GS.end_turn()` → `turn_processor()`，植物和敌人依次行动，然后发新牌。生长逻辑在 `plants/Plant.gd` 的 `take_turn()`：

- 回合结束时植物身上有 ≥1 点水，就扣 1 点水并推进一帧生长
- 已经到最后一帧时，再满足一次水量要求即结算收获
- 缺水则不生长，并扣 1 点生命
- 每株最多可存 10 点水，所以可以提前囤水，不必每回合都打水牌

各档种子的成熟周期：

| 种子 | 场景 | 生长帧数 | 长到满级 | 可收获 |
|---|---|---|---|---|
| 基础种子 | `Plant1.tscn` | 4（种子 + 3 阶段） | 第 3 回合结束 | 第 4 回合结束 |
| 中级种子 | `Plant2.tscn` | 6（种子 + 5 阶段） | 第 5 回合结束 | 第 6 回合结束 |
| 高级种子 | `Plant3.tscn` | 6（种子 + 5 阶段） | 第 5 回合结束 | 第 6 回合结束 |
| 神秘种子 | `WinPlant.tscn` | 9（种子 + 8 阶段） | 第 8 回合结束 | 第 9 回合结束 |

## 核心设计想法

### 玩法定位

游戏是基于卡牌的策略经营：玩家用卡牌浇水、种植、防御、攻击，经营农场并积累卡组。四季是叠加在经营循环之上的节奏层，让同样的地图和资源在每个阶段呈现不同压力，而不是独立的小游戏模式。

基本闭环：

```
买种子 → 播种 → 按轮次浇水 → 成熟 → 收获卡牌/金币
   ↑                                      │
   └──────── 扩充卡组、解锁图鉴 ←──────────┘
```

### 生长与跨季

- 种子按"有效浇水轮次"成熟，不是按现实时间
- 每种种子有可种植季节，非当季不能种
- 不同种子成熟所需轮数不同，长周期种子会跨季：例如每季 6 轮时，春播 12 轮的种子会在秋季收获
- 缺水的那一轮不推进生长，收获轮次相应顺延
- 植株的血量跨回合、跨季节保留，不会因为换季自动回满
- 需要明确"越冬规则"，这是跨季玩法的核心规则，建议三选一：
  - 方案一：冬季休眠。植物不生长也不死，需要取暖/保温才能继续积累生长进度
  - 方案二：冬季照常生长。规则最简单，但冬季缺乏特色
  - 方案三：冬季冻死。压力最大，容易造成不可控损失，不建议作为默认规则

倾向方案一：冬季休眠 + 取暖可继续生长，既保留风险，也给玩家应对手段。

### 季节机制

每个季节有不同的环境修正，目前的想法：

- 春：适合播种，暂定无额外惩罚，可考虑生长或播种相关加成
- 夏：浇水需求翻倍，例如每推进一轮需要 2 点水
- 秋：暂定无额外惩罚，可考虑收获加成或品质提升
- 冬：需要选择取暖卡牌/取暖状态；取暖后一次浇水可以覆盖两轮生长

机制建议做成可配置的"季节修正值"，而不是写死在各个脚本里：

- `water_need_mult`：每轮生长所需水量倍率
- `growth_steps`：一次浇水推进的生长阶段数
- `yield_mult` / `quality_bonus`：收获数量或品质加成
- `plantable_seasons`：哪些种子可以播种
- `enemy_pressure_mult`：敌人强度或频率修正

### 种子获取与刷新

- 种子在商店购买，商店库存随机刷新
- 不同季节刷新不同的种子池，鼓励玩家按季节规划种植
- 种子有稀有度，稀有种子对应更长的生长周期和更好的产物
- 商店当前只有固定的永久升级商品（能量上限、农田、抽牌数、自动浇水），没有随机种子库存，需要新增商品与库存逻辑

### 植株图鉴

- 每种植物第一次成熟后加入图鉴，作为长期收集目标
- 图鉴记录：植物各生长阶段、首次成熟季节与年份、累计收获次数、最佳产量
- 图鉴完成度可以给奖励，例如解锁新种子、卡牌、装饰或商店折扣
- 图鉴是跨局保存的元进度；单局内的农田、植物、卡组则属于单局状态

### 存档范围

想让"跨季长周期 + 图鉴 + 商店刷新"成立，至少需要保存：

- 单局状态：当前轮次、季节、季节内轮数、金币、能量、卡组、手牌、抽牌/弃牌堆、田地上的每株植物
- 每株植物：种子 id、生长阶段、当前水量、血量、防御、播种季节与轮次、已积累的有效浇水轮数
- 元进度：图鉴解锁与统计、已解锁种子、货币、商店库存

建议单局存档与元进度分开存，避免重开一局时把图鉴清空。

## 设计评估与建议

### 有潜力的地方

1. 跨季长周期作物天然形成"提前规划"的策略深度，和卡牌经营结合得很自然
2. 季节限定种子池让每个季节都有不同的构筑选择，重复游玩价值高
3. 图鉴提供跨局长期目标，能显著提升留存
4. 夏季浇水翻倍、冬季取暖这类环境规则，能让同一套卡组在不同季节有不同打法

### 需要提前想清楚的风险

1. **越冬规则必须先定。** 如果长周期作物会在冬季冻死，玩家就必须精确计算播种时点，容错很低；如果冬季完全不影响，跨季就只是"等轮数"。建议采用"冬季休眠 + 取暖继续生长"，并在 UI 上标出预计收获季节。
2. **夏季浇水翻倍和 3 点能量经济可能冲突。** 目前每回合 3 点能量、每回合抽 5 张牌，基础水滴卡 0 费给 1 点水。夏季每轮要 2 点水，意味着两株植物就会吃掉全部免费水，其他卡很难打。建议至少选一个缓冲：夏季水牌效果 +1、部分耐旱作物不受影响、或把"翻倍"改成"每两轮额外消耗 1 点水"。
3. **取暖不要做成纯随机卡牌。** 如果玩家抽不到取暖卡，长周期作物就会被动受损，这属于不可控的失败。建议做成：每季开始时固定获得一张取暖卡；或取暖是场景设施/状态，用金币或行动开启；或卡组外单独一个"季节卡"槽位。
4. **四季机制目前不对称。** 夏冬是惩罚，春秋没有明确机制，玩家会感觉春天只是"安全的等待期"。建议给春秋正反馈：春季播种费用降低或生长加速，秋季收获数量/品质提升。每季都有得有失，节奏才完整。
5. **长周期作物必须有明显更高的回报。** 12 轮作物占用田地和每轮行动，如果收益不比 4 轮基础作物高，玩家不会种。建议让长周期作物产出稀有卡牌、图鉴条目或独特材料，而不是单纯更多金币。
6. **季节限定 + 随机商店会造成"错过等一年"。** 建议保证每次商店刷新至少有 1 个当前季节可种的种子；对尚未解锁的图鉴种子提高出现权重；并提供种子仓库或跨季兑换，避免玩家因为 RNG 卡死收集进度。
7. **图鉴解锁时机建议定在"首次收获"。** 如果只是长到最后一帧就解锁，玩家可能种下后不再管理，靠时间白拿图鉴；以收获为准更符合经营循环。
8. **"种子血量"需要区分概念。** 当前 `Plant.gd` 里的 `health` 是植株血量，已经会跨回合保留。种子本身是否需要耐久/品质是另一套设计，建议不要混用同一个字段。
9. **季节惩罚不要和敌人强度同时拉满。** 现有敌人在无敌人 3 回合或连续 12 回合后刷新。夏季高水耗再叠加高强度敌人，容易形成无法应对的双重压力。建议季节修正与敌人压力错开，或让冬季敌人更少但环境更难。
10. **存档是这套设计里最大的工程量。** 当前项目没有持久化系统，`GS.reset_all_state()` 会清空全部状态。需要先设计存档 schema 和写入时机（建议每回合结束、换季、购买后写入），并加版本号方便后续迁移。

### 设计节奏建议

- 先做"视觉四季 + 轮次切换"，不改任何数值，先验证观感和节奏
- 再加"季节限定种子池"和"图鉴"，这两项对玩法结构影响最大
- 最后加"夏季浇水翻倍 / 冬季取暖"这类数值机制，便于单独调平衡
- 存档在加入跨局图鉴之前完成，否则图鉴数据无处保存

## 技术实现草案

### 状态与触发

- 新增 `SeasonManager.gd`，挂在 `Game.tscn` 下，或做成全局单例
- 维护：当前季节索引、当前季节已进行轮数、每季轮数配置
- 在 `GS.end_turn()` 的回合处理完成后递增轮次，达到阈值就调用 `apply_season(next)`
- 季节顺序：春 → 夏 → 秋 → 冬 → 春

需要注意：`GS.end_turn()` 里已经有敌人刷新计数（`no_enemy_turns`、`some_enemy_turns`），季节计数应单独维护，不要复用这两个变量。

### 素材替换

预览脚本里已经验证过完整的替换流程，可以直接迁移：

1. 遍历 TileSet 的 1–10 号图块，按文件名映射从 `res://seasons/<season>/farm/` 加载并 `tile_set_texture()`
2. 遍历 `TileMap/Decor` 下的 Sprite，把 `texture.resource_path` 中的 `res://decor/` 替换为 `res://seasons/<season>/decor/`，再 `load()` 赋回
3. 春季直接还原为原始资源路径

为避免切换卡顿，建议首次进入游戏时预加载三季纹理并缓存到字典，之后只做指针替换。96 张像素图内存占用不大。

### 数据模型草案

建议把"种子"和"植物实例"拆开：

**种子定义（静态数据）**

- `id`：唯一标识
- `name`：显示名
- `seasons`：可种植季节列表
- `growth_rounds`：需要多少个有效浇水轮次成熟
- `water_per_round`：每轮基础需水量（夏季可被季节倍率修正）
- `yield_cards` / `yield_gold`：收获产物
- `rarity`：稀有度
- `shop_price`：商店售价
- `art`：各生长阶段贴图

**植物实例（运行时状态）**

- `seed_id`
- `stage`：当前生长阶段
- `water`、`health`、`defense`
- `planted_round`、`planted_season`
- `effective_waterings`：已推进的生长次数
- `frozen` / `heated` 等季节状态标记

**季节状态**

- `season_index`
- `rounds_in_season`
- `year`
- `season_length`

### 存档草案

建议 `user://save.json`，结构分两块：

```
{
  "version": 1,
  "meta": {
    "collection": { "<seed_id>": { "first_season": "...", "harvests": 0, "best_yield": 0 } },
    "unlocked_seeds": [],
    "gold": 0,
    "shop_stock": []
  },
  "run": {
    "round": 0,
    "season": "spring",
    "rounds_in_season": 0,
    "plants": [],
    "deck": [],
    "hand": [],
    "draw_pile": [],
    "discard_pile": [],
    "energy": 3,
    "gold": 0
  }
}
```

写入时机建议：回合结束、季节切换、商店购买、图鉴解锁。存档带 `version` 字段，后续改结构时可以迁移。

当前 `GS.reset_all_state()` 会把金币、卡组、能量等全部重置，接入存档时需要区分"新开一局"和"读取单局"。

### 表现与反馈

- HUD 增加季节图标或文字，以及"距离换季还剩 N 轮"
- 切换时用全屏遮罩做一次短淡入淡出，遮住贴图整体替换的瞬间
- 可选：切换时播放对应季节的环境音或粒子（春花瓣、夏萤火、秋落叶、冬飘雪）

### 风险与注意事项

- 编辑器中打开 `Game.tscn` 时，外部脚本改动后要选择"重新加载"，不要保存编辑器里的旧版本，避免把 TileSet/素材引用覆盖掉
- 季节素材必须保留 `.import` 与 `.stex`，否则 Godot 会重新导入并可能造成首帧卡顿
- 运行时替换 TileSet 纹理后，已放置的图块不会丢失，只是显示贴图变化
- 装饰物是独立 Sprite，替换纹理不影响位置、缩放和层级

## 里程碑建议

1. M1：调试用季节切换（按键 1/2/3/4 立即换季），验证所有图块和装饰物替换正确
2. M2：接入轮次计数，按固定轮数自动循环
3. M3：HUD 展示当前季节与剩余轮数，加入切换过渡
4. M4：完成存档基础结构（单局 + 元进度），保证后续系统有地方落数据
5. M5：季节限定种子池 + 商店种子刷新 + 可种植季节校验
6. M6：植株图鉴（首次收获解锁、阶段展示、统计与奖励）
7. M7：季节玩法机制（夏季水耗、冬季取暖、春秋加成）与平衡调整
